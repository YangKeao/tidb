# b072 — twelfth native radix/code expression-kernel deletion tranche

## Scope

This receipt records the current deletion checkpoint, not a completed
`pkg/expression` transcreation. The tranche physically deletes native `HEX`,
`UNHEX`, `BIN`, `OCT`, `ORD`, and `BIT_COUNT`, their type-aware wrappers,
private byte/radix coercion helpers, native unit modules, and all residual
value/scalar dispatch. AST, contextual-value, values-only and scalar boundaries
refuse these names before evaluation. Ordinary admitted shapes execute only in
TiKV.

Source-kind and NULL-mask boundaries are fail-closed contractions: HEX over
binary literals or non-lowerable TRANSLATE/NULLIF children, OCT binary-literal
forms, and numeric/non-leaf ORD. OCT's ordinary string signature executes in
TiKV. Former Go values remain beside each
contraction. The TiKV lowering bridge now selects `HexStrArg` for string,
temporal and duration input, while decimal/real/int use `HexIntArg`; the source
datetime and typed TIMESTAMP regressions failed before this correction and pass
after it. JSON is declined before signature selection because its inferred HEX
result width (`8 * MaxBlobWidth = 34359738360`) cannot pass the bridge's checked
protobuf-i32 metadata conversion. `CastJsonAsString` itself is supported;
constant and typed-column Go values are kept as exact contractions for this
composition-level gap.

## Preserved seventh-tranche post-review hardening

A follow-up audit found that the first receipt incompletely carried several
source inputs and that three difftest drivers accepted removed-family errors by
marker alone. The current receipt supersedes that behavior:

- all deleted miscellaneous vectors are retained, including non-UTF8 UUID
  wrappers, UUID text/binary/swap variants, shard arities/string values, both
  cast-warning inputs, and generic-index/malformed decoder keys;
- expression/query contraction acceptance requires a parsed AST builtin node
  and its exact family marker; names inside literals/comments cannot qualify;
- integration visible calls use the same AST identity, while prepared/default
  expressions use exact topic+complete-statement equality plus the marker; and
- `ANY_VALUE` is never a miscellaneous contraction. Only the native backend may
  classify its exact refusal; Copying/Borrowed execution errors remain errors and
  executable statements require success plus a positive TiKV expression-row delta.

The hardened native replay records 77 `NativeContraction` statements plus one
`NativeOnlyRefusal`; the 160 carried unrelated divergences remain visible.

  this renderer sizes fractions by written digits, and the unsigned-wrap

  (maketime_float_second_maxfsp_and_unsigned_cast_rows ignored stub).

## Bounded-staleness follow-up (2026-09-04)

The previously ignored `TestTiDBBoundedStaleness` row is now active. Rust's
`TIDB_BOUNDED_STALENESS` dispatch accepts the two ETDatetime endpoints,
rejects invalid-zero values through the statement truncation policy, returns
NULL for a reversed window, and chooses the statement SafeTS when it falls in
the inclusive window (otherwise clamping to the lower or upper endpoint).
The result is retagged as DATETIME(3), matching Go's
`setDecimalAndFlenForDatetime(3)`. `Columns::bounded_staleness_safe_time` is
the narrow context seam for a storage-provided/failpoint SafeTS; a context
without storage deliberately falls back to the lower endpoint.
