# 共享表达式执行器实施计划

## 目标

Rust TiDB 和 TiKV 在同一进程内调用同一个表达式执行器，保留各自的输入格式、类型推导及宿主上下文。共享程序负责子树需求、短路、转换时机、批执行和函数调用。已有底层算法由其所属库维护。函数族清单固定为 245 项，已登记的实验例外仍单列。总改动按两仓相对原始基线的新增加删除计算，目标为 10K 数量级。 [固定设计](https://github.com/YangKeao/tidb/blob/ddb87c63ff2d0dbe40ede1e84d4b1182b6541cbe/rust/docs/expression-shared-kernel-design.zh.md)

## 源码与工作树

产品工作树为 `/home/agent/tidb/expression-shared-kernel/tidb` 及同级 `tikv`。原始 TiDB 为 `364aef2bab5cc633ecb76a775ae8f36f86a6687d`，SDK 为 `548812e1ef57aef077a2062a9cc356640a6347f5`。独立 SDK checkout 位于 `independent-sdk/tikv`，验证实际独立编译时不要从相邻 TiDB 借用路径。

TiDB `rust/crates/tidb-expr/src/shared_kernel.rs` 负责编译及输入输出接入。SDK `components/tidb_query_expr/src/types/{expr,expr_builder,expr_eval}.rs` 使用同一个 `RpnExpression` 与执行循环。TiDB 本地 Projection、Selection 和 Unistore 负责各自生命周期及声明。既有实验由显式设置选择，生产默认沿用原入口。

## 后续实施

按固定清单扩展可证明的签名。先核对原生绑定后类型、实际载体、所需参数和副作用，再在同一程序中复用既有比较、逻辑和数值机制。SQL 的转换与错误语义、PB 的 eager 和受标志控制的时机及 Unistore 的请求上下文各有原合同。在进入候选执行前核验调用声明与载体，执行错误直接返回。以真实调用证明重用，推进排序键、聚合参数及其他仍独立执行的入口。

保留一个冻结程序跨实际批使用，独立执行隔离状态。默认切换前验证完整可达的签名、原本支持的输入和故障行为。通过同一程序与值输出契约迁移后，再移除已无调用的旧求值实现。兼容例外与外部宿主能力须逐项说明。

## 验收

每批保留原生／共享和实际存储对照，注明错误、告警、需求和字段声明。验证默认及启用构建、独立 SDK 和真实 TiDB SQL。整体验收还需要原始与最终 release 的分段计时、分配对照和 SQL 性能支持。每次统计均计入移动的新增与删除，分类列出源码、测试、构建以及材料。当前原生路径、固定清单覆盖和性能仍在验证中。
