# Expand local reuse across TiKV's supported expression functions


This is a living ExecPlan governed by repository-root `PLANS.md`. It extends an experimental embedding, not a claim that the Go expression package has been transcreated or its original implementations removed.


## Purpose / Big Picture


The user asks to adapt as many functions already supported by TiKV as possible and discover concrete problems. Replace the small arithmetic/LENGTH-only admission boundary with a measured, reproducible capability surface. Preserve native execution as the default, retain explicit copying/borrowed choices, and document unsupported types, missing mappings, context differences, eager control-flow behavior, and semantic disagreements rather than admitting unsafe expressions to inflate coverage.

The deliverable must distinguish an enum entry from an actually dispatched TiKV signature, a facade-callable signature from an automatically selected TiDB SQL mapping, and an owned-column call from a borrowed call. An adapter using original kernels is not a replacement kernel implementation.

## Surprises & Discoveries


Initial source inventory finds 640 upstream ScalarFuncSig enum variants including Unspecified, but only 510 listed in the TiKV RPN dispatcher. The local TiDB Rust protobuf enum has only 233 variants: 290 actually dispatched signatures are absent locally. This need not force changing protobuf definitions: the local prost Expr.sig field holds an optional raw i32; wire IDs can come from the pinned engine's signature-name lookup.

The baseline TiKV standalone facade whitelists 52 signatures; TiDB further narrows automatic local selection to 23 unique signatures / 13 function names. These counts must be regenerated by the inventory script, not treated as permanent constants.

TiKV RPN in this checkout has only Constant, ColumnRef and FnCall nodes. Its builder traverses child expressions before the parent, so IF/IFNULL/CASE/COALESCE/AND/OR kernels do not make their child expressions lazy. A fallible or warning-producing unused branch can still execute. Preserve original TiKV semantics at the low-level facade and exclude unsafe lazy trees in the TiDB adapter; do not pretend an eager expression tree becomes lazy through function-name mapping. The differential matrix has an explicit fixture: `IF(0, int_max+1, 7)` compiles to `None` (native) and never runs the overflow.

Usable TiKV evaluation types are Int, Real, Bytes, Decimal, DateTime, Duration, Json, Enum and VectorFloat32. Set appears in type enums but is not supported by the native type/codecs. Some mapper arms index children before validation (LIKE and ToBinary), and mutable JSON/vector backing representations need ingress validation. Broad admission requires boundary hardening, not merely deleting a whitelist.

Real SQL JSON and LONG BLOB/TEXT columns use `flen = 4294967295` (Go `MaxBlobWidth`), which `i32::try_from` refused in both the local compile schema and `pushdown_catalog::field_type_to_pb`. The local adapter now narrows that single sentinel to `-1` exactly as Go's `ToPBFieldType` does, in a local helper; the shared pushdown catalog is unchanged.

Two kernel-level safety holes were found by adversarial review and are now guarded before execution in the standalone facade: fractional-digit arguments to ROUND/TRUNCATE with extreme values (`TRUNCATE(0.0, 309)`, `ROUND(1.0, -400)`) panic inside `NotNan` arithmetic, and finite vector/real kernels can emit `Inf` that a following arithmetic node feeds to `Real::new(...).unwrap()`. The standalone-only checked RPN entry validates each produced Real vector before the next node; the stock TiKV `eval_decoded` path is unchanged.

Genuine semantic divergences found by the enrolled mysql-tester replay (`difftest-result-tests --test integration_diff`): TiKV `UuidVersion`/`UuidTimestamp` accept malformed UUID strings where Go raises error 1411, and TiKV `Ord(NULL)` returns 0 where Go returns NULL. Both were previously native; they are now excluded from local admission (with a leaf-only NULL mask wrapper for ORD's otherwise-equivalent valid inputs). `Greatest`/`Least` over unsigned integers compare raw `i64` in the legacy kernels; the adapter compares exact Decimals and casts back so `UInt` values above `i64::MAX` keep SQL order.

With the engine enabled, the enrolled 110-topic / 10,255-statement replay produces the *same* 142 divergences as the native baseline (byte-identical sets; the native run asserts zero engine rows). Those 142 are pre-existing plan-text/row divergences of this working tree, not adapter regressions. `difftest-result-tests --test expr_diff` (two `EXPORT_SET` string-argument cases) and `join_shape`'s stale ratchet constant are red identically with the feature off.

The earlier Go IF/GET_LOCK source audit identified a separate suspected planning-time constant-fold side-effect bug. It was not runtime reproduced, is not automatically fixed by this work, and must not be counted as a verified issue in the new adapter.


## Decision Log


- Decision: preserve both previous branches and all previous benchmark datasets. Rationale: isolate broad semantic adaptation from earlier copy-removal measurements.
- Decision: use the existing RPN builder and kernel metadata constructors, not a second hand-written kernel registry. Rationale: casts, IN, regex and temporal units rely on metadata beyond names and argument counts.
- Decision: replace the PoC facade's Decimal text transport with exact native decimal values and add the other native value families. Rationale: text formatted with result scale can discard hidden fractional digits; a type bridge must not silently change intermediate values.
- Decision: preserve explicitly opted-in borrowed loaders rather than automatically generating loaders for every newly exposed function. Rationale: many signatures have custom evaluators, metadata and additional context requirements. A requested borrowed backend may safely use copying before any evaluation when no borrowed implementation exists.
- Decision: local broad lowering remains separate from distributed pushdown authorization. Rationale: changing network predicate policy is outside this request and can lose rows before local filtering.
- Decision: compile refusals choose native before evaluation; execution errors never trigger replay. Rationale: warnings and side effects cannot generally be rolled back.
- Decision: generate raw signature IDs from the pinned engine rather than manually extending the local protobuf enum. Rationale: preserve wire compatibility and avoid unrelated generated protocol changes.
- Decision: keep `uuid_version`/`uuid_timestamp` native after the replay proved TiKV accepts malformed UUIDs where Go raises 1411. Rationale: broad coverage must not change diagnostic behavior; a faithful UUID validator at the boundary is future work.
- Decision: implement `GREATEST`/`LEAST` over unsigned integers as exact-Decimal comparison plus the original typed cast, and `ORD` as a leaf-only `IF(StringIsNull(x), NULL, ORD(x))` wrapper. Rationale: reuse existing kernels while restoring SQL semantics the legacy kernels do not implement; no kernel is modified.
- Decision: add a standalone-only checked RPN entry that validates produced Real vectors, leaving stock `eval_decoded` unchanged. Rationale: prevents valid finite inputs from reaching a panic in a later node while preserving TiKV server behavior.
- Decision: narrow the `flen = 4294967295` blob/JSON sentinel to `-1` in a local wire-metadata helper, matching Go's `ToPBFieldType`. Rationale: real SQL JSON/LONG columns must be encodable without widening the shared pushdown catalog.
- Decision: `EXPORT_SET` string-argument divergence and the stale `join_shape` ratchet constant are recorded as pre-existing, not fixed here. Rationale: they reproduce identically without the `tikv-expr` feature and are outside the adapter boundary.

## Validation and Acceptance

It does not require falsely asserting complete parity or all 510 signatures automatically selectable. All automatically admitted calls must preserve documented type/context rules; known unsafe shapes must choose native before executing any engine kernel. Runtime failures must not cause a second native evaluation.

Broad owned-only signatures must not increment borrowed counters. Test eager unused-branch failure at the low-level facade and native preservation at the TiDB boundary. Add RED/GREEN regression evidence for any actual bug fixed, including malformed expressions that could panic or lose precision.
