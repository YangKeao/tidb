# 并行投影的共享 BIGINT 计算

TiDB 固定在 `60b886823691d4c6e6bd3a1ba00ef9038e239c40`，SDK 固定在 `2e123f71eb9b20e6e46b32110d60f895f7d8830b`。

开启共享投影后，符合并行条件的本地 SELECT 可接纳两个直接有符号 BIGINT 操作数的加减乘，并同时输出原列。现有工作队列依旧按取批顺序交付。SDK 程序元数据可移动，不能跨线程共享引用，因此每次打开投影时为每个并发槽准备一份等价程序和执行对象，求值任务独占借用后归还。编译发生在首次取批前，批间复用已准备的程序；槽池锁只保护借还。

真实 SQL 用 2 个并发槽处理 5 个单行批次，核对了顺序、重复原列、NULL、告警及原 1690 溢出文本。含 RAND(7) 的并行组走原路径。开放范围的流水线窗口查询也验证了并行计算输入键，覆盖有无 Shuffle 两种计划。

61 项执行器集成、81 项共享表达式、14 项窗口筛选、功能关闭构建、限定 Clippy 和根 lint 通过。并发槽内存、吞吐与延迟未测。
