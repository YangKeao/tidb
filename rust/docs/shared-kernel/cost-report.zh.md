# 245族共享表达式迁移成本核算

本轮结论：**当前路线没有证据支持总修改约10K**。在保留底层存储、字符集、计划编解码及服务库的前提下，剩余源码与测试的条件预算为 **36,470–79,760行增删**；加上checkpoint7已测的5,870行，为约 **42,340–85,630行**。这不是数学下界或保证上限，不能把估计低端当成不可减少的必要代码。最大成本是时间语义、旧执行入口退役、JSON、全类型转换与字符串兼容。

这份清单用于选下一批工作，不表示245族已经兼容。最小数值／控制／状态机制通过设计审查，完整M1生命周期、正式Clippy、默认入口、产品兼容和性能仍未完成。

## 最大成本为什么在这里

1. **时间6250–12800行**：`time_fn`的日历运算、复合间隔、负duration、日期文本解析、SQL mode、FSP、DST／时区和statement clock都参与结果。`time_literal`还属于构建阶段。不能因为SDK已有`date`或`add_date`就把57族归为小幅映射。区间低端共享SDK解析／运算并补策略，高端搬表达式算法但保留底层Time、timezone库；若必须改底层时间表示则超出本区间。
2. **入口与退役4550–10300行**：必须覆盖AST、Expression、SimpleExpr/PB、projection/filter/sort/aggregate和Unistore。`ScalarFunction`同时拥有类型、缓存和构建信息；不能整体删掉5838行。只退役已替代的运行时递归、逐函数参数求值和向量分派，保留结构与公开适配入口。该项不再次计入各组已列的叶子算法删除。
3. **JSON4300–8850行**：复用SDK二进制JSON并不能自动保留原生ParseToJSONFlag、文本／typed JSON区分、数字精度、路径缓存、对象呈现及CRC32。路径解析、共同值转换、比较／呈现函数只在JSON组计一次，schema外部依赖与会话能力另列例外组。完整JSON存储／索引codec不移动。
4. **全类型转换3500–8100行**：目前只接纳有限String→Real和数值载体。剩余unsigned、enum/set/bit、Decimal列、time/duration/JSON/vector、结果形状和严格／告警策略仍需共同转换层，不能在每个函数里重写一次。`cast`、`arg_eval_type`、`coerce`的表达式逻辑计这里；planner类型推导和存储codec保留。
5. **字符串3800–7800行**：字符／字节索引、Unicode大小写、排序规则、原始Bytes与String载体、max_allowed_packet与函数特定告警共同决定可复用范围。共享字符串帮助函数去重；GBK等字符集转换单列，不搬字符表来伪装算法迁移。

## 五个例外逐项处理

- `tidb_decode_plan`：`builtin_ext/info.rs:53`调用`tidb_util::plancodec::decode_plan`，无效输入保留原文。`tidb-stmtsummary/src/reader.rs:1128`等仍消费codec。共享的是表达式需求／结果策略，codec保持原所有者。
- `tidb_decode_binary_plan`：同文件65行调用binary decoder，无效输入返回空串并追加1105，不能与文本decoder合并错误策略。executor EXPLAIN和statement summary仍使用codec。
- `tidb_encode_sql_digest`：同文件39行调用`tidb_parser::normalize_digest`，不能替换为对原文本直接SHA。server与session仍用normalizer；保留parser能力，经明确的函数能力接入共享循环。
- `validate_password_strength`：`builtin_ext/crypto.rs:478`消费会话身份／全局密码策略与`tidb_util::password_validation`；`tidb-session/src/account.rs:270`仍需账户校验。只计表达式能力与错误桥接，不搬账户子系统。
- `json_schema_valid`：`builtin_ext/json/report.rs`缓存PreparedJsonSchema，draft201909验证并延迟解析外部引用。NULL文档不得提前触发HTTP／文件读取；需检查参数重绑定、context id、validator缓存以及错误文本。底层schema／HTTP库继续保留，不能把整个service伪装成通用表达式回调。

例外组580–2000行预算只覆盖这些**具体能力接口、表达式组合和差分测试**。底层服务本体未算成免费移动；假设保留现有所有权。如果crate依赖或服务协议迫使整体迁移，新增／删除与测试是未界定额外项，须先单独定价。五项仍是原245分母内的待处理功能，不退出覆盖目标。

## 未界定项与预算失效条件

- **逐签名兼容闭包尚未证明**：245族不是245个同质函数；SQL mode、字符集、type flags、native/PB入口会扩成更多组合。逐族表给出差异检查合同与源码见证，没有把未运行的差分称为通过。新增未知差异会扩大范围。
- **值表示／crate依赖**：如果必须统一整个native/SDK时间、JSON、Decimal存储表示，而不是表达式载体和少量公共算法，本表上限失效。不能恢复通用host-resume协议或第二求值器来绕过这个问题。
- **删除闭包**：trait方法、re-export、宏和动态调用不可能靠本次文本扫描证明全部归属。删除前必须逐个实际调用者编译／测试，未迁移调用者所需算法不能删；如果继续保留旧默认执行，必须从删除预算中撤回对应额度并说明目标未完成。
- **测试／fixture**：预算假设复用现有测试和输入，新增目标边界对照；不复制现有几十万行测试到第二个执行器。若数据重录／大量既有测试修订必需，其增删和原始数据也需计入。全量检查尚未通过，不能从31／429项推出这个额外工作为零。
- **算法新增与外部库**：原SDK没有生产声明见证不代表必须复制native整文件；原有库也可能有可用primitive。反过来，若需要新增依赖或修改底层库，不能只计算一行调用和忽略lockfile、依赖输入及兼容验证。
- **性能**：共享架构不等于性能达标。默认SQL和release测量尚无数据；针对性能的额外实现成本未界定，不含在上述上限中。

## 总量、下一批选择与本轮验证
