# 本地串行投影与 PB 共用 AND／OR 指令

Task #51 按 984e81b5。验证固定在 TiDB `99030ae697233fdc159bf7110e51a0cf81df2486` 和 SDK `6114b86f4f6076933e7a50b7a88b9569a1bf5af4`。 [SDK 固定源码](https://github.com/YangKeao/tikv/commit/6114b86f4f6076933e7a50b7a88b9569a1bf5af4)

## 编译与求值

本地有符号、非数组 BIGINT 二元 AND／OR 在原有迭代编译中发射 `LogicalStart`、`LogicalNext` 和 `LogicalEnd`。签名要求两个操作数及结果都有该声明，字面量还须有 Int 或有类型的 NULL 载体，已有子表达式按共享编译和冻结校验接纳。完整原生布尔声明仍从原表达式保存。无符号、数组、非整数、类型与值不符和未接纳子树在准备阶段整组回退。

两端沿用 SDK 的同一个指令循环、逻辑帧、三值合并、未决行选择及冻结检查。左假 AND 和左真 OR 跳过右侧，左 NULL 仍请求右侧。本批新增原生的三条指令发射与目标重定位。SDK 的开头指令增加调用模式选择，PB 仍进入向量模式，原生沿用外层 `OrderedRows` 的标量模式。PB 预解码和开关沿用原入口，TiDB SQL 默认为原路径。新建的 SDK `LogicalStart` 需指定 `preserve_mode`。

## 原生对照

输入 `[3,0,2,1,0]`，带负数和 NULL 的 `(a OR b) AND c` 与原生逐行均返回 `[NULL,1,0,NULL,1]`。

带活跃或跳过的 `BENCHMARK(2, RAND())` 右侧，输入 `[2,0,1,0,2]`。OR 有六次随机流调用，返回 `[NULL,1,0,1,NULL]`；AND 有八次，返回五个零。原生逐行、共享显式标量、同一共享执行中的两批向量调用对上。短路的整型溢出右侧成功跳过，左值要求右侧时（包括左 NULL）仍返回原有 1690 及 `BIGINT value is out of range in '(9223372036854775807 + 1)'`。用原先的无条件向量调用替换模式选择，活跃 BENCHMARK 测试失败并报 `invalid repeat invocation`。移除逻辑终点偏移时，嵌套用例在冻结时报 `invalid shared control program`。

## 真实 SQL

`SELECT (a OR b) AND c, RAND(7) FROM logic_samples ORDER BY id LIMIT 5` 在五行实际表数据上保留计算投影。显式开关打开时，修复前选中／批次计数为 `(0,0)`，修复后为 `(1,2)`。游标实际给出 `[2,3]` 两批，与原生的逻辑结果 `[1,NULL,0,NULL,1]` 及跨批 RAND(7) 序列逐值相同。布尔字段声明完全相同，包括 BIGINT、长度 1 和 IS_BOOLEAN 标志。关闭开关时无共享计数；开启开关但将操作数换成无符号列时，包含 RAND(7) 的整组计数仍为 `(0,0)`，字段和结果与原路径相同。
