# DOUBLE 比较与原生 NaN 语义

task #71 固定为 TiDB `f036016af9ddd0134fdd8bebc66709f372f15e6e` 和 SDK `2db2644ad954c2a0dfd8535e1fb82c97460ee631`。

七种原生 DOUBLE 比较通过同一个 RPN 函数调用。现有 CmpOp 负责有序结果和 NULL，原生 DOUBLE 保留 NaN 的无序行为。已准备的调用明确标记可读取原生载体。普通 PB 函数的载体检查和比较规则沿用原路径。

类型化测试在 81 个值对及一条重复物理行上核对七种比较，覆盖两种 NaN 位模式、负零、无穷和 NULL。NaN 对 EQ 及 NULL 安全相等为假，对 NE 为真。单行调用也通过。真实 SQL 的投影和 Selection 均从 (0,0) 变为 (1,1)，字段、结果和告警一致。

75 项共享表达式、21 项 SQL、独立 SDK 444 项表达式、122 项执行器和 3 项 Endpoint 检查通过。限定 Clippy、根 lint 和两仓格式通过。本批未测性能。验证目录 `evidence/double-comparison/` 重建 16 对跟踪源码树，其中 10 对固定到产品版本，保留了早期载体拒绝及修正过程。清单包含 72 条记录，`SHA256SUMS` 的 SHA-256 为 `eb688ed99f66af584bbb937988099556c5a7e509c2095fbf2388483e0c784753`。
