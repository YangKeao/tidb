显式开启的本地串行投影可同时接收直接列和已接纳的计算列。计划绑定时核对直接列的子节点、表达式和输出字段声明。计算根保持原相对次序，在同一 RPN 程序中完成后，暂存列和直接列都用原有 `ColumnSwapHelper` 转交。每次执行复用暂存 Chunk。只包含计算根的投影继续写入输出 Chunk。只含直接列、任一计算根无法接纳及启用并行 worker 的投影走原分支。非空列传递继续遵守原生的选择向量限制。

`ORDER BY COALESCE(v,id), id LIMIT 3` 的实际 SQL 含 TopN。原版本保持正确结果且共享计数为 (0,0)，固定版本为 (2,2)。两个版本的输出字段、结果和告警相同，ID 顺序为 4、2、3，含重复的 VARBINARY 列与 NULL。另一个查询在两个连续的两行批次间保持种子 RAND 序列及直接列值，计数为 (1,2)。含直接列的溢出路径仍返回原 1690 诊断并消耗同样的会话 RNG。纯列和含 ABS 的混合组均保持 (0,0)。

固定版本通过 12 项 SQL、68 项共享表达式及 1 项默认 PREPARE 检查。限定 Clippy、根 lint 和格式验证通过，保留原有告警与驱动文件的既有格式差异。本批未测性能。固定源码与补丁仅覆盖所记录的跟踪文件，完整构建依赖未封存。
