# 直接 BIGINT 比较的批执行

Task #57 的测试源码为 TiDB `aae7ceef403bd159497ce76f5cbdf4eef16d38b3` 和 SDK `dcec7b0394e1b2b6d6e5d4a8f34bd84d64fa4b69`。基线 TiDB 为 `cc133762aa92c068ebf3fa85ccdaf615cfe326bb`，SDK 相同。

原生有两个直接列或字面量的 BIGINT 比较可按一批喂给既有 RPN 比较器。编译器仍验证声明和值域，执行上下文仍决定调用模式。复合操作数和有副作用的表达式保留原生逐行时机，Unistore 也保留左 NULL 时停止的标量路径。PB 和默认 SQL 的选路沿用原设置。原始基线的顺序比较会插入 `OrderedRows`。加入结构断言后，旧版失败，新版的列比较从列引用直接开始，原生逐值对照及需要逐行的断言通过。

## 同一批投影的 release 对照

实际 Chunk 有有符号和无符号列，覆盖边界值、NULL、倒序和重复位置。每版都在计时前后按原生逐行结果核对输出。测量相同的计算投影写 Chunk，分别运行原生 EvaluatorSuite 与已有共享直接输出。固定 CPU 23，六轮交错两版和两条路线，构建为 opt-level 3、无 LTO、16 个 codegen 单元。计时从已准备好的程序开始，含该次投影的输出处理。
