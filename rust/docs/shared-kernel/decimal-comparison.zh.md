# DECIMAL 比较与精确排序

task #72 固定为 TiDB `441bd284a91999664614aa9d8d63d134a9d2616f` 和 SDK `070c1b2cad01fe60ecc4fdb108fbd824bb7c4ca0`。

七种同类型 DECIMAL 比较通过原有 RPN 函数调用，与 DOUBLE 共用 NULL 和比较结果分派。DECIMAL 按原生 datatype 的顺序比较完整系数和 scale。当前每次比较把原生载体还原为 Decimal，宽值需要复制。本批未测开销。混合类型、UNSIGNED 声明和需要额外转换的签名继续走原有入口。

类型化测试核对 36 个值对和一条重复物理行上的七种比较，包括宽值最低有效位差异、不同 scale 的相等值、负数、NULL、真实 Chunk 以及单行调用。另验证精确字面值和混合类型拒绝。实际 SQL 的投影和 Selection 都从 (0,0) 变为 (1,1)，字段、结果和告警一致。

76 项共享表达式、22 项 SQL、独立 SDK 的 444 项表达式、122 项执行器和 3 项 Endpoint 检查通过。限定 Clippy、根 lint 和两仓格式通过，保留既有告警。验证目录 `evidence/decimal-comparison/` 重建 14 对跟踪源码树，其中 10 对对应固定产品版本。清单包含 64 条记录，`SHA256SUMS` 的 SHA-256 为 `9c9a4c7c88827aa667991a4c53f16967c63238cf9bbe7c806cb4272059da6955`。
