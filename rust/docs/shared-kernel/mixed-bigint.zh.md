# 本地 BIGINT 比较的四种符号组合

Task #55 固定在 TiDB `c965510488546e207e2356e7d946a97f44a63e3a` 和 SDK `69a3c0c3a3dcd9316131f27ea96ef64e022cd7e9`。 [SDK 比较选择器](https://github.com/YangKeao/tikv/commit/69a3c0c3a3dcd9316131f27ea96ef64e022cd7e9)

原生 EQ／NE／LT／LE／GT／GE／NullEQ 和 SDK PB 现在共用同一个有符号性选择器。SDK 的四种比较实现沿用原代码。有符号或无符号的 BIGINT 列、匹配的整数字面量和类型化 NULL 可作为原生比较操作数。列按存储位模式读取，比较按两个声明分别解释，比较结果仍是原生的有符号布尔结果。数组、声明与值不符、无符号的独立输出或需要子表达式转换的无符号操作数继续从候选接纳之外走原入口。原生 AND／OR 与 Unistore 有符号比较范围沿用。

真实 Chunk 中按四组合、七算子、每组 28 个实际结果与原生逐值比对，共 784 个值。覆盖 i64 最小值、-1、最大值、u64 最大值和跨 i64 最大值边界、NULL，以及倒序和重复选行。追加字面量 u64 最大值和类型化 NULL。旧版本在有符号／无符号比较准备时拒绝。

保留本地 Selection 的实际 SQL。带符号和混合符号的组均选中一次、运行三批，行、告警和会话随机流与原路径一致。原生比较换成 DECIMAL 转换后整组计数 `(0,0)`，结果与原路径一致。默认 SQL、PB 请求标志和 Unistore 开关不变。
