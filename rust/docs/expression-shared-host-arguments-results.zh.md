# 表达式复用：统一参数状态与删除冗余包装

本轮把18类函数的参数收集、任务状态和结果发布放到现有共用路径，并删除失效额度参数、无输出的树遍历、重复校验和不会失败的返回包装。保留实际 SQL 求值顺序、NULL 短路、类型转换、告警、回调后的校验和真实分配错误。最终源代码提交是 `43ba91c201769b0d7d9930e2da3488870e95ca6f`；此报告和验证记录在其后的文档提交中，不改变被测实现。

本轮相对 `e94b3c53dec9a80395e640e03171549217285918` 净减生产代码2582行，测试净增63行。统计包含空行，按测试文件及 `cfg(test)` 模块区分，文档不计入。不是从项目最初 base 到现在的净删行数，也不把先前保留的5159行再次计入本轮成果。

最终995项检查为994通过、1项相同基线失败；14场景224个测量单元、140244次查询完成。Decimal/JSON的CPU四轮均下降，摘要、时间差和深表达式则四轮均高于两个同版对照；摘要的成对中位变化为+2.842%／+2.560%。按要求保留简化待审阅，性能不作为全面无回退证明。JSON_SUM_CRC32 的标准SQL入口仍受既有 ARRAY 转换限制，本轮没有其SQL性能数据。

### SQL 场景修正及既有边界

最初完整预检在 JSON_SUM_CRC32 的测量 SQL 上失败，四个进程标签均报相同语法错误，其余13场景等价，尚无计时数据。按照解析器要求改为 `JSON_SUM_CRC32(expr AS UNSIGNED ARRAY)` 后，A、C、F实际服务均被现有 rewriter 的 ARRAY 转换拒绝。另尝试引用内部函数名的入口也未成功，探测结果一并保留。这些是既有入口限制，没有为性能测试修改解析器或实现新功能。

最终第14场景使用已支持的 `JSON_UNQUOTE(JSON_EXTRACT(IF(id%23=0,NULL,JSON_OBJECT('k',id%7)),'$.k'))`，用于检查 JSON 构造和提取路径；第13场景保留 DATE_ADD/DATE_SUB。原先12场景的查询完全不变。JSON_SUM_CRC32 值内核具有单测覆盖，但本轮**没有它的 SQL 性能数据**，不可用这个替代场景声称已经测过该新合并内核。

测量表使用原有8192行 fixture 的派生表；该表不含存储 JSON 列，JSON 测量均由真实输入 id 构造。原表保留到测试清理时；本轮不声称验证了存储 JSON 列的读取能力。

### 最终测量结果

北京时间 2026-11-13 01:25:15 至 01:41:52，有效测量实际退出码0，用时997.769秒，完成224个单元、140244次完整查询。56次严格预检、448条前后观测记录（共672次完整观测）和计时数据核验通过。未观测到已知编译、测试或 perf 进程；全部自建服务和两处临时数据库目录已清理。

A和B使用完全相同的先前保留 ELF，C是本轮候选，F是项目原始 Rust 服务。四轮使用平衡顺序，每个标签各处在四个位置一次；每个单元至少4秒且至少30次查询。每条查询执行并取回全部结果。测的是整条 SQL 的服务端进程 CPU 和端到端时延，包含规划、RPC、编码等成本，不能当作表达式内核的独立耗时。

会话设置UTC，并实际读取确认 init_chunk_size=32、max_chunk_size=1024、vectorized=1。第一轮负载检查满足静默条件；正式启动前的第二次检查仅因自建PD在16秒内使用0.66秒CPU而不满足原来严格的“无活跃进程”阈值，四个服务核心占用均低于5%，没有编译/测试/profiler。按最新要求保留实际负载和同版对照，不将普通后台活动作为延期理由。
