# Real TiDB/TiKV SQL smoke — round230

## Scope

This is a narrow localhost smoke against three real OS processes: one PD, one TiKV, and one TiDB, reached through the MySQL protocol. It is not an exhaustive SQL compatibility run, a frozen/current comparison, a release benchmark, or a concurrent production-QPS measurement.

The TiDB Go server does not link `rust/crates/tidb-expr`; therefore this run does **not** exercise the experimental TiDB Rust `EvaluatorSuite`/lane cache. The TiKV server was built from the paired current TiKV source and does include its `tidb_query_expr` coprocessor implementation. `EXPLAIN FORMAT='brief'` confirms that the measured expressions below ran in `cop[tikv]`.

## Correctness smoke

The 4,096 rows contain nullable signed integers, non-null integers, binary-collated UTF-8 strings, `DECIMAL(20,2)`, and JSON. Every tenth row has NULL in `i`, `s`, `d`, and `js`.

The SQL set covers:

- integer PLUS, multiplication, and `ABS`;
- lazy `IF`, `COALESCE`, and `NULLIF`;
- `STRCMP`, `LOWER`, `CHAR_LENGTH`, and `CONCAT`;
- Decimal addition;
- `JSON_TYPE` grouping and `REGEXP_LIKE` filtering;
- `MD5`, `LENGTH`, `UPPER`, `SUBSTRING`, and a prepared parameter;
- SQL warning projection for `CAST('not-a-number' AS SIGNED)`.

The output of `correctness.sql` is byte-identical to the independently generated expected TSV (`correctness.diff` is empty). The warning query was run separately and is not part of that byte-for-byte oracle. Representative correctness results are:

```text
4096  3686  25076  -5541  89627
60425 2419   -549   17608 24980
Decimal sum: 1119698.61
REGEXP_LIKE count: 1093
MD5('abc'): 900150983cd24fb0d6963f7d28e17f72
prepared SUM(i + 7): 25081
```

The separate warning observation was `1292 Truncated incorrect INTEGER value: 'not-a-number'`; it was inspected but not checked by the TSV diff.

The previously observed experimental Rust release failures for `MD5` and column-backed `length(s)` did not appear here, but that is **not** evidence that those Rust paths are fixed: this Go TiDB server does not call them.

## Confirmed TiKV pushdown

The integer plan contains:

```text
HashAgg cop[tikv]: sum(plus(t.i, t.j)), count(1)
Selection cop[tikv]: gt(plus(t.i, t.j), 0)
```

The mixed plan contains:

```text
HashAgg cop[tikv]: sum(if(gt(t.i,0),t.i,t.j)), sum(plus(t.d,0.55)), count(1)
Selection cop[tikv]: regexp_like(t.s,"^[at]","i")
```

Thus the real RPC/coprocessor path was exercised for integer PLUS/filter/aggregation and for IF, Decimal PLUS, and regexp filtering.

## Sequential timing smoke

Each timing run reused one MySQL connection and emitted one scalar result row per statement. Runs alternated integer/mixed order. A separate post-run audit—not an inline runner assertion—counted and hashed every timing output: each integer run returned exactly 2,000 identical `58479\t2081` rows, and each mixed run returned exactly 1,000 identical `27843\t407904.83\t1776` rows. The compact audit is retained as `bench-output-check.txt`; the large repetitive outputs themselves are not committed.

| workload | statements/run | elapsed runs | median per statement | median sequential rate |
|---|---:|---:|---:|---:|
| integer pushed aggregate/filter | 2,000 | 1.58 / 1.55 / 1.50 s | 0.775 ms | 1,290 statements/s |
| mixed pushed aggregate/filter | 1,000 | 0.88 / 0.88 / 0.84 s | 0.880 ms | 1,136 statements/s |

These numbers include MySQL parsing/protocol, planning/execution, localhost TiDB↔TiKV RPC, scanning 4,096 rows, coprocessor execution, and result delivery. They use one client, one store, warm data, no durability/fault/concurrency pressure, an unoptimized TiKV build, and no frozen comparator. They must not be generalized to production QPS or used to compare the Rust lane-cache microbenchmark.

## Server-log audit and cleanup

A post-run scan of the three retained complete server logs found no `FATAL` or panic and produced `server-error-lines.txt`. Startup logged unavailable heap profiling, a missing harness cgroup `cpu.max`, permission denial for TiDB's default optional DDL-ingest sort directory, and one transient/context-canceled leader-router stream creation error; the tested table creation/inserts and exact correctness oracle still completed. The later TiKV resource-group and TiDB TSO connection errors occurred while the single-node cluster was being torn down. These environment/startup/teardown records are retained rather than silently omitted, and this run does not validate DDL ingest or heap profiling.

The final runner recorded all six ports free after teardown. A separate post-run check also confirmed the PD, TiKV, and TiDB HTTP endpoints were unreachable and all six listening ports were absent. The runner bounds cleanup by allowing a three-second SIGTERM grace period and then forcing termination only for any process that remains alive.
