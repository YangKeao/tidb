Checkpoint `binary-three-47`, round48, follows `unary-two-46`. Frozen ids `plus`, `minus`, `mul`: functional delegation/native deletion **160/245**, strict final-audited0, acceptance target221. The previous157 entries remain unchanged. This is an experiment, not PR-ready or whole-domain acceptance.

- Native `tikv/evaluated_ascii*`, `tikv/mod.rs`, `lib.rs`: adapters and narrow legacy/fast SDK. Causes are actual typed reports; resources never become SQL overflow. The facade transports fast outcomes without re-decoding/recomputing them.

## Closed protocol, without a parallel driver
43 new unit recipes: native Int13/IEEE3/Decimal3/vector3/NULL1; legacy Int12810/IEEE3/Decimal3/missing1; fast Decimal3. Exact ids are in `checkpoint.json` and the Plan.

`Decimal2` physically carries two actual Decimal operands plus an infrastructure budget Int, using the new `DecimalBinary` role. Both real spill capacities count; three slots produce four nodes, within the old factory default. `Int1282` carries two complete LE16 values, not narrowed ints. IEEE pairs retain actual `ReadyIeee754Arg::Value` values; vector pairs use existing typed input. Genuine `NullWitness(None)`/`NoArgs` cover NULL/missing; an invalid Some witness is rejected, never a fake SQL value.

Owned results: Int15, IEEE6, Decimal6, vector3, Int12810, DecimalFast3. The sole new result is `Unsupported | Value(None | Some(NativeDecimalFastValue))`. Wire None is real SQL NULL, `[0]` means Unsupported, and tag1 plus LEi128 coefficient/two LEu32 scales is25 bytes. A single strict TiKV decoder validates shape; native code only moves the outcome. Bad encoding remains infrastructure/quarantine. Existing checked-i64 view and vector result decoder are reused with only the declared operation extensions.

Native errors are exact semantic operation/domain on allowlisted recipes; legacy integer errors retain operation/signedness. Authentication additionally requires the actual `EvaluateError::Caused` object and this call's +1 dispatch witness. Closure, shape, bridge, budget and allocation failures never acquire SQL overflow credit. Ordinary PB and legacy admission, six-slot backing storage, factory limits and the common driver remain unchanged.

## Preserved policies and deletion
- Native `0-i64::MIN` follows the original Go-style predicate; wire signed subtraction still uses checked subtraction. Native mixed unsigned multiplication uses original raw u64 bits; wire mixed multiplication still rejects a negative signed operand.
- Original `NO_UNSIGNED_SUBTRACTION` demand stays at non-NULL subtraction preparation, once. No fake SQL boolean argument or hidden origin tag selects a policy.
- Native real rejects non-finite results; legacy real keeps IEEE Inf/NaN. Native Decimal overflow becomes its typed SQL cause; legacy Decimal keeps the returned warning value.
- Public MySql multiplication keeps its unsigned-coefficient i128 eligibility, full Grow computation, nine-word projection, signed zero on overflow and original rounding/storage scales. Exact arithmetic remains separate. Wire Fixed storage and zero policy remain unchanged.
- Signed batch fast retains checked alignment, right-hand checked negation before subtraction, and its own multiplication scale/range rules. In particular MIN-MIN may be Unsupported even though the ordinary shared Decimal result is0. The batch evaluates all left cells, then all right cells, stages all results before append and propagates resource errors; only actual Unsupported permits the ordinary TiKV row path. A SQL NULL is not Unsupported.
- Legacy integers keep full i128 inputs until computation/result range checking. PlusInt is signed, including the historical oddity that PlusIntSignedSigned belongs to the unsigned variants. Mixed plus/minus rejection rules and forced/ordinary minus distinctions are unchanged. Integer children remain eager; real and Decimal remain left-to-right with missing/NULL short-circuit. Error text preserves `BIGINT UNSIGNED` with its real space and ADD/SUBTRACT/MULTIPLY.
- Public Decimal facades and coefficient/projection consumers share the TiKV leaves. Native runtime paths do not retain a business fallback. Vector layout copying is explicit; there is no zero-copy or heap-peak claim.

1. Original Grow multiply used only one base reduction. With only that old branch restored, the independent B=1e9 identity `(B²-B-1)(B²-3B-1)=(B-4)B³+B²+4B+1` failed: actual `999999995000000001000000004000000001` versus expected `999999996000000001000000004000000001`. Restore the second reduction for Grow/native policy; all86 Decimal tests pass. Wire Fixed is unchanged.
2. CPP test compilation needed an actual trait import and one existing test's exhaustive rejection arm. Its real overflow test then failed because the sealed IEEE readiness allowlist omitted the six real recipes. A diagnostic replay exposed InvalidSpec before kernel execution. Add exactly those six closed operations: arithmetic30 and local284 pass.
3. Native compilation needed the actual ReadyIeee754Arg constructors. Its arithmetic79 tests passed. SQL then exposed integer batch `_=>None`, returning NULL under a zero-slot policy. Preserve whole-left/whole-right demand and route only +,-,* NULL cells through the real witness and existing bits packer. The unchanged SQL assertion passes; final native arithmetic refresh and full suites cover the integrated source.

No old SQL or new expected values were changed, no fixture was recorded, and no source behavior was redefined from provider output. Compile failures, diagnostic replays, and formatter/source-tool incidents are all disclosed in the [16-receipt summary](../logs/binary-three-summary.txt).
