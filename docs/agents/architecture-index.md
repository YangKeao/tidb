# TiDB Architecture Index for Agents

This file is a navigation index for quick subsystem discovery.
Hard requirements remain in the repository root `AGENTS.md`.

## How to Use This Index
1. Map the task to one primary subsystem.
2. Find existing tests covering the same behavior.
3. Reuse existing fixtures/testdata before creating new shapes.
4. Expand to adjacent subsystems only when cross-module effects are clear.

### Rust shared-expression experiment
- `rust/crates/tidb-datatype/src/collation.rs` retains the SQL-facing collation facade; migrated General/UCA key and LIKE kernels are owned by the sibling TiKV checkout's `components/tidb_query_datatype/src/codec/collation/`. Its `native.rs` centralizes explicit native collation policy selection for compare/key/LIKE/COW/capability helpers; `Collation::native_policy()` is the checked identity mapping, not a wire-ID conversion or global-mode lookup. Its `gb.rs` owns GB compare/key and native GB encoding leaves; `multibyte_encoding.rs` is a GB facade while non-GB encodings remain unchanged. Explicit wire/native policies preserve PUA key-only NULs, NoPad, codec versions and the nine wire-only overrides. The original four TiKV data tables and canonical 2103-pair mapping are the only owners; generators verify them and reject the deleted native duplicate images/mappings. From `rust/`, use `cargo test --locked -p tidb-datatype --test all shared_collation_contract -- --test-threads=1`. The parser-charset default-registry assertion remains non-green; see `docs/expression-unification/evidence/substring-gb-checkpoint.md`.
- `rust/crates/tidb-datatype/src/tikv_compat/` is the checked shared-value boundary. Complete SQL `FieldType` metadata remains TiDB-owned; the initial bridge admits Int/Real/Bytes and NULL, not full Decimal/temporal/JSON unification.
- `rust/crates/tidb-expr/src/like.rs` and `rust/crates/tidb-util/src/stringutil.rs` delegate matching to that shared kernel. TiDB's general expression evaluator has not yet been replaced by this foundation checkpoint.
- Private `rust/crates/tidb-expr/src/tikv/` contains an explicit, crate-internal signed-BIGINT leaf/control seed: `lower.rs` retains SQL/PB metadata, `context.rs` imports demanded physical row occurrences, and `batch.rs` owns each worker's official TiKV RPN program. It is not a global evaluator hook or native fallback. `distsql_builtin.rs` retains shallow wire provenance before conversion loses presence/signed-ID information.
- TiKV `components/tidb_query_expr/src/local/{batch,compile}.rs` and `types/expr_eval.rs` share a closed fixed-argument evaluator for seventy-seven families, including LN, LOG (both arities), LOG2, POW/POWER, UNCOMPRESSED_LENGTH and INSERT. Checkpoint20 also repairs previously missed legacy LOWER/UPPER paths; the earlier complete-family claim was overstated until this repair. `EvaluatedArgs` covers true NoArgs, nullable Bytes/Int/Int2/Bytes+Int/Bytes×3/IEEE754Bits and typed packet arguments; canonical slots and fixed one/two FnCall recipes share the same driver, with owned Int/Bytes/IEEE-bits results. Raw math recipes use closed private getters with common preparation, not invented wire signatures. Negated boolean tests use base+UnaryNot with ordered identity checks, not the NULL-distinct opposite IS test. Old ASCII/Bytes APIs are thin entries. Binary/UTF-8 and HEX Int/Bytes variants are connected, not partial-family credit. `string_fn.rs` and `builtin_ext/string2.rs` retain frontend coercion/packing but no duplicate kernels for the migrated families; `build.rs::BuiltStringLength::{eval,eval_in}` also delegates LENGTH for public helpers and typed row calls. `rust/crates/tidb-expr/src/math_fn/mod.rs` retains CRC32 raw UInt packing (existing SQL inference remains signed). `rust/crates/tidb-expr/src/string_signature.rs` supplies existing Go normalization for REVERSE/main CHAR_LENGTH; QUOTE retains its Rust lossy normalization. `rust/crates/tidb-expr/src/scalar_function/pb_builtin.rs` routes typed CHAR_LENGTH to the shared helper, and `rust/crates/tidb-unistore/src/cophandler.rs` routes legacy SimpleSig counting while preserving its distinct Rust normalization. From `rust/`, the legacy regression is `cargo test --locked -p tidb-unistore --lib legacy_char_length_keeps_rust_lossy_grouping_before_shared_kernel -- --test-threads=1`.
- Private module `rust/crates/tidb-expr/src/tikv/evaluated_ascii.rs` now exports explicit native policy/owner/execution/scope capabilities and `AsciiScope::evaluate_value`, using only the real closed TiKV worker. The Sized borrowing `ScopedAsciiColumns` forwards63 ordinary methods and overrides two effective-capability queries. Existing active scope wins; wrapper, execution and body-unwind guard use that same scope. Getter-discovery panic conservatively quarantines only the requested scope, not an undisclosed hidden one. Frontend coercion precedes admission. Root-stable creating/live/idle/retiring accounting remains conditional on independent pinned allocation-request evidence, not factory high-water or physical heap. The seventy-seven functional families delegate here; `evaluate_args_in` guards its supplied coercion/packing closures and `evaluate_bytes_in` is its thin wrapper. Bitwise operators retain their pre-normalization and diagnostics in `rust/crates/tidb-expr/src/ops.rs` and `ops/{integer_coerce,real_coerce}.rs` before the ready-argument helper; six results retain UInt bits while BIT_COUNT stays signed. `rust/crates/tidb-expr/src/lib.rs` exposes the closed `BooleanFunction`/`eval_boolean_ready_in` normalized truth/presence seam used by legacy unistore as well. AST/typed/PB conversion distinctions stay intact; `scalar_function.rs::vec_eval_bool` declines NOT/ISNULL before child evaluation and removes their old answer-producing fast paths. `LogicalFunction`/`LogicalArgs` retain original eager/lazy child demand; `UndemandedRight` is accepted only for AND(false, _) or OR(true, _), otherwise ScopeContract before factory/dispatch. Its validated representative is not evaluated RHS data. Closed-ready compilation emits the actual official eager FnCall; ordinary Row/wire control remains lazy. BETWEEN also uses the shared AND, while XOR gains no PB/unistore admission. Ordinary SQL does not gain ISTRUE_WITH_NULL admission. `rust/crates/tidb-expr/src/builtin_ext/crypto.rs` now sends MD5/SHA/SHA1 through the existing Bytes driver, retaining `hash_input` and text packing but deleting local digest/hex calculation for these routes. PASSWORD's separate parser/auth double-SHA1 algorithm and unmigrated SHA2/SM3 consumers remain outside this claim. `rust/crates/tidb-expr/src/builtin_ext/compare2.rs` also delegates the four INET families using the existing Bytes/Int shapes; it retains checked text/raw-byte conversion, NTOA integer diagnostics and UInt/binary/text packing. Four IS_IP predicates now use private nullable wrappers over the original TiKV algorithms, preserving wire NULL-to-zero separately. Only IPv4 input spelling removes redundant segment-leading zeros; validation and results stay in TiKV. The native parsers/prefix checks are deleted, while shared raw-byte conversion remains. Broader frontend operation-scope guards remain a follow-up, while operation-keyed cached/idle workers share one root and retire before debt is released. Active scopes/executions are borrowed; without either, an explicitly bounded experimental TiKV one-shot execution handles the value (never native fallback). The separate session module owns configured execution lifetimes. Complete business-operation scope reuse and performance remain follow-ups. From `rust/`, use `cargo test --locked -p tidb-expr --lib tikv::evaluated_ascii::tests::`. Its ignored observer fixture alone does not measure allocations.
- `lib.rs` and `scalar_function.rs` keep their distinct TRIM child/coercion order and route prepared values through `string_fn.rs::trim_value_in`. All directions, NULL and empty removal enter real TiKV wrappers over one trim core; native sequential-right and original wire independent-right overlap policies differ explicitly. `string_fn.rs::substring_index_in` keeps two-string coercion and signed/unsigned count preparation, not splitting; its dedicated ready role distinguishes actual NULL from an undemanded count. `string_packet.rs::pad` keeps length cast/1292, packet/1301, range, then two-string coercion. The four pad recipes use typed whole-group ReadyBytesArg markers and real four-column inputs. These four pad operations, the two INSERT operations and `Locate3Native` permit five caller compile nodes; other recipes retain four, depth three. TiKV alone constructs/truncates padding with native/wire envelopes; existing wire nonzero equal-length empty-pad and MIN-abs defects are not silently fixed. From `rust/`, use `cargo test --locked -p tidb-expr --lib trim_subidx_pad_dispatch_ -- --test-threads=1`.
- `math_fn/mod.rs` keeps LN/LOG/LOG2 domain diagnostics and POW finite-result policy over real raw IEEE kernels. `Ieee754Bits2` accepts a single undemanded side only for POW with a genuinely NULL peer; native, PB and legacy argument demand remain distinct. `lib.rs::eval_raw_pow_ready_in` and `RawPowReadyArgs` connect `cophandler.rs` without masking legacy NaN/Inf. `builtin_ext/crypto.rs` keeps short-header1259 but delegates NULL/empty/full-LE32 UNCOMPRESSED_LENGTH. `string_fn.rs::str_insert` prepares original operands; TiKV owns range/splice with binary versus true native character boundaries and raw replacement bytes. `func.rs` applies packet policy only after the computed result, with no packet getter for NULL. `lib.rs::eval_raw_case_ready_in` connects four legacy case signatures: ASCII high octets remain unchanged, UTF8 retains Rust grouped-lossy preparation before existing Go-simple kernels, and NULL reaches C4. From `rust/`, run `cargo test --locked -p tidb-expr --lib log_pow_ulength_insert_dispatch_ -- --test-threads=1` and `cargo test --locked -p tidb-unistore --lib legacy_case_ -- --test-threads=1`. These are core checks, not final workspace or performance acceptance.
- `string_fn.rs::{field_with_collation,make_set_in,export_set_in}` retains frontend domain selection/coercion and delegates comparison, selection and generation to dedicated TiKV prepared recipes. FIELD uses shared single-candidate probes only to preserve coercion cutoff, then a real kernel validates the prefix and returns the index; SQL children stay eager. MAKE_SET's native unchecked-shift policy remains distinct from wire behavior, including the value-only mask argument. `builtin_ext/string2.rs` keeps EXPORT_SET's strict tuple/LTR preparation separately from the value helper's whole-list NULL precheck and lossy conversion. The TiKV EXPORT_SET core is new compatibility code, not reuse of a pre-existing wire implementation. From `rust/`, run `cargo test --locked -p tidb-expr --lib set_field_dispatch_ -- --test-threads=1` and `cargo test --locked -p tidb-expr --lib builtin_ext::string2::tests -- --test-threads=1`; SQL checks use the existing `evaluated_ascii_` session filter.
- `string_fn.rs::ConcatPreparation` centralizes frontend coercion, demanded-prefix collection and packet diagnostics for value and typed CONCAT/CONCAT_WS; `scalar_function.rs` keeps lazy child evaluation but no output join. A dedicated TiKV prepared payload carries full SQL arity and real nullable operands, not a four-argument subset or prejoined result. `lib.rs::concat_values_in` supplies the context-aware public helper; `concat_values` remains a compatibility wrapper. `oct_in` keeps raw64/text dispatch and `elt_in` keeps selected-Datum conversion; TiKV owns octal scanning and ELT's shared demand/final selector, without changing eager SQL-child evaluation. From `rust/`, targeted checks are `cargo test --locked -p tidb-expr --lib concat_stream_dispatch_ -- --test-threads=1` and `cargo test --locked -p tidb-session --lib evaluated_ascii_ -- --test-threads=1`.
- `string_fn.rs::{strcmp_with_collation_in,locate_in,locate_with_position_in,position_with_collation_in}` retain coercion and explicit collation/units selection, not comparison/search algorithms; `func.rs`, `lib.rs` and `scalar_function.rs` supply actual execution contexts. POSITION's AST helper keeps character units even with Binary comparison. The separate extension LOCATE3 entry in `builtin_ext/string2.rs` preserves wrapping-position and exact-unit policy. FIND_IN_SET there uses NoPad key equality, not sort comparison; its opaque TiKV-prepared key owner replaces the native HashMap while `BuiltinFuncCache` keeps context-once list evaluation, error retry and clone invalidation. Build/probe collation policies remain independent snapshots. `tikv/mod.rs::prepare_find_in_set_keys` maps the actual pure-builder error without claiming a worker Prepare/Invoke phase. Only the new `Locate3Native` recipe extends the specific four-column/five-node whitelist; ordinary graph admission is unchanged. Core checks from `rust/`: `cargo test --locked -p tidb-expr --lib collation_search_dispatch_ -- --test-threads=1`; SQL checks: `cargo test --locked -p tidb-session --lib collated_search_set_dispatch -- --test-threads=1`.
- `string_fn.rs::substring_with_contexts` prepares two/three-argument SUBSTRING/SUBSTR/MID without range or slice algorithms. `builtin_ext/string2.rs` preserves the two-argument `NoColumns` cast policy while using the actual execution context for C4. PB retains its source-reader and NULL demand order and actual-arity selection. `lib.rs::eval_raw_substring_ready_in` connects all four legacy signatures through `RawSubstringInt` and true Two/Three argument variants; the shared `legacy_substring_needs_len` predicate returns only demand, never the SQL answer. TiKV alone owns start/end/slicing and legacy width rejection, Rust-lossy policy and unchecked addition. Native and Legacy substring roles are distinct; only legacy uses validated 16-byte i128 operands. From `rust/`, run `cargo test --locked -p tidb-expr --lib substring_dispatch_ -- --test-threads=1` and `cargo test --locked -p tidb-unistore --lib legacy_substring_ -- --test-threads=1`.
- `string_fn.rs::case_convert_in` and `case_convert_signature_in` route aliases and PB binary/UTF8/NULL branches to real TiKV kernels. Text retains only Go per-malformed-byte normalization; the native casing adapter is deleted. Fixed private UTF8 getter bindings preserve the empty-charset/zero-heap descriptor contract instead of invoking the charset-dependent wire selector. `builtin_ext/crypto.rs` retains SHA2 coercion/demand only; TiKV `impl_encryption.rs` owns its sole selector/digest/hex core, with native quiet NULL versus original wire warning1583. `ReadyIntArg` replaces the packet-specific count name; SHA2's independent BytesIntReady role validates undemanded length. `string_fn.rs::ord_with_type_in` preserves argument-charset preparation and `scalar_function.rs`'s typed ETString entry. TiKV alone folds prepared bytes; all three ready entries enforce the proven four-byte bound. Existing latin1 is byte-preserving, not silently reinterpreted. From `rust/`, use `cargo test --locked -p tidb-expr --lib case_sha2_ord_dispatch_ -- --test-threads=1`.
- `rust/crates/tidb-expr/src/string_packet.rs` keeps packet sizing/1301 policy and coercion for SPACE/REPEAT/TO_BASE64, not result algorithms. `string_fn.rs` routes both FROM_BASE64 surfaces; its value-only entry keeps execution context but omits packet policy. Typed packet dispositions travel with real nullable arguments; actual private TiKV wrappers produce suppressed NULL. REPEAT's explicit undemanded count is accepted only with NULL left input and Allow, then lowered to a documented irrelevant non-NULL representative. `impl_string.rs` shares unique cores with official wrappers: empty REPEAT avoids billions of empty iterations; native Base64 policy differs in length/whitespace checks without copying codecs. Native Text versus Binary tags stay intact. From `rust/`, the core filter is `cargo test --locked -p tidb-expr --lib packet_string_dispatch_ -- --test-threads=1`.
- PI uses `lib.rs::eval_pi_in` and true NoArgs: zero columns/schema entries and one actual zero-argument FnCall over one output row. Its private wrapper calls the existing TiKV pi function rather than duplicating the constant. AST/typed/PB and legacy routes share this entry; legal SQL constant folding is unchanged and is not evidence of a runtime call. `ClosedPrivate` selects both math and nullable IP wrappers, with input role checked independently.
- TiKV `impl_math.rs` owns six raw-f64 primitives used by its original Real wrappers and private IEEE-byte wrappers; `local/registry.rs` rejects their private IDs outside the closed factory. IEEE role and exact eight-byte transport checks do not weaken Real/NotNan. Native `math_fn/mod.rs` keeps coercion, SIGN's coefficient-based sign/zero-class adaptation and output policy, not the mathematical algorithms. `lib.rs::eval_raw_inverse_trig_ready_in` preserves legacy NaN; ordinary ASIN/ACOS map it to NULL. `cophandler.rs::LegacyEvaluator` carries typed SQL versus infrastructure errors through real/int/decimal/json/bytes/time/duration and interval paths, preserving old SQL folding and demand order. Public string errors are rendered only at the old boundary. Review its method-indentation change with `git diff -w`; regression filter from `rust/`: `cargo test --locked -p tidb-unistore --lib legacy_inverse_trig_ -- --test-threads=1`.
- Private `rust/crates/tidb-expr/src/tikv/runtime_failure.rs` owns an opaque native handle to the original LocalError. Only the handle and its native class/phase enums are re-exported; constructor, cause access and payload stay private. `context.rs::EvalError::ExpressionRuntimeFailure` preserves shared cause identity and native-only Debug. The terminal arm in `rust/crates/tidb-executor/src/driver/errors/exec.rs` uses its fixed message through existing1105/HY000 and Eval-origin handling. The explicit value API captures Prepare/Observe/Invoke at actual failing calls; public value-produced Prepare and pool-resource failures have dedicated terminal-mapping tests. The ASCII dispatcher now reaches this value boundary; SQL zero-slot failures also exercise the adapter path. Natural Observe-error execution, complete operation-scope propagation and broad fold/default diagnostics remain unverified. From `rust/`, use `cargo test --locked -p tidb-expr --lib tikv::runtime_failure::tests::` (eight tests); the executor renderer filter is `cargo test --locked -p tidb-executor --lib driver::errors::exec:: -- --test-threads=1`, with one independently characterized pre-existing Sequence origin-equality failure, not an all-green claim.
- `rust/crates/tidb-expr/src/tikv/adapter_failure.rs` separately retains original Pool/Scope/Bridge causes behind a native opaque Arc; its class/origin do not fabricate backend failures or replace SQL evaluation-origin handling. From `rust/`, use `cargo test --locked -p tidb-expr --lib tikv::adapter_failure::tests::` (nine tests, including the explicit native `AsciiOwnerError::into_eval_error` conversion), and `cargo test --locked -p tidb-executor --lib driver::errors::exec::tests::public_ascii_value_ -- --test-threads=1` for the two actual public value-to-terminal error cases.
- `rust/crates/tidb-session/src/ascii_runtime.rs` holds the optional, explicitly configured session evaluator pool and separates lexical nesting from detached-result close ownership. `stmt_ctx.rs` carries the same execution into `rust/crates/tidb-executor/src/stmt_context.rs`; clone/COW never rotates epochs. `record_set.rs` closes captured executions, not Session.latest; Session Drop invalidates before other cleanup. From `rust/`, targeted checks are `cargo test --locked -p tidb-session --lib tests_core::lifecycle:: -- --test-threads=1` and `cargo test --locked -p tidb-executor --lib stmt_context::tests:: -- --test-threads=1`.
- `rust/crates/tidb-datatype/src/field_type/memory.rs` provides `checked_snapshot_payload_bytes` for pre-copy logical metadata budgeting. It borrows visible elements, includes the independent private binary-marker length and checks arithmetic without allocating snapshots. It does not measure allocator capacity or make observation/copy atomic: the owner keeps aliases stable during that interval. FieldType equality/hash can allocate element snapshots, so new bounded adapters apply this byte gate first. Its eight inline tests use `cargo test --locked -p tidb-datatype --lib field_type::memory::tests::snapshot_payload_` from `rust/`, not the generated integration target.
- PB provenance keeps its detached effective type private: `FieldType::clone` shares mutable Go-style element backing, so immutable specifications cannot expose that baseline through shallow clones. The lowerer compares it through a predicate; inspection snapshots detach the backing.
- `rust/crates/tidb-expr/src/rewriter/preparation.rs` supplies a bounded, explicit StructuralOnly boundary through the purpose-aware builders in `rewriter.rs` and `new_function.rs`. Existing public wrappers remain SqlBuild. Structural trees retain declared metadata, not value-refined nullability/precision; explicit signed CAST can be prepared but is not admitted for execution by the private seed. - Private `rust/crates/tidb-expr/src/tikv/ordinary.rs` provides the separate signed-PLUS row seed. Typed trees contain no PB state; PB trees are checked occurrence-for-occurrence against the trusted retained original wire during lowering, then release that borrow. Binding checks native Int/NULL before transport can erase UInt identity; each computed node owns its result metadata. Its raw-runtime entry preserves local errors and does not activate a public route. `rust/crates/tidb-expr/src/tikv/ordinary_diagnostics.rs` adds an optional private, own-spec diagnostic plan and checked native overflow view: exact kernel/site/domain joins precede typed1690, own PLUS rendering is distinct from nested PB display names, and the raw cause remains recoverable. - Private `rust/crates/tidb-expr/src/tikv/lineage.rs` adds the separate native Datum SQLTypedRow control boundary. Its all-node no-PB type proof, sparse producer IDs and own program/table preserve selected Int/UInt and String/Bytes/collation identity; predicates reject transitively possible UInt. Complete source and incoming-schema payload gates precede allocating snapshots/equality. The demanded read checks kind/collation before transport erasure; materialization accounts for the retained core values, IDs and native output together, without promising a hard allocation peak. Inspection returns detached FieldType snapshots. It does not compose ordinary calls, the private overflow view, native batch, or public SQL routes. Its focused command from `rust/` is `cargo test --locked -p tidb-expr --lib tikv::lineage::tests:: -- --test-threads=1`.
- Private `rust/crates/tidb-expr/src/evaluator/numeric_batch.rs` owns the closed signed-203 native-batch caller. `evaluator.rs` shares its actual dispatch with a mandatory private consumer while public `run` remains native; `scalar_function.rs` separates unchanged eligibility from the native value worker. The invocation token is minted after Decimal priority and one current vectorization-flag read, never by executing a worker as a probe. It joins its own program/calculated slot/source tree, checks full incoming metadata and chunk layout before effects, copies the actual selection once and checks native Int/NULL on the demanded read. Only one calculated tree and no ColumnSwap/leaf/row/PB/parameter routes are admitted. Source, selection and fixed native Int output coexistence have separate retained checks; aliases remain owner-stable and there is no hard-peak claim. Raw/reported failures do not use the row diagnostic or control-lineage domains. From `rust/`, run `cargo test --locked -p tidb-expr --lib evaluator::numeric_batch::tests:: -- --test-threads=1`.
- `rust/Cargo.toml` records the experimental sibling TiKV checkout relationship and caller-side dependency patches. Kernel reuse is in-process and does not itself require a TiKV/PD service.

## Practical Search Workflow
1. Start from symptom:
   - SQL keyword
   - error message
   - variable name
2. Find implementation entrypoint:
   - planner/executor/expression/session/ddl/store
3. Find existing tests around the same behavior.
4. Confirm neighboring modules only if call chain crosses boundaries.

## Common Cross-Module Paths
- Planner -> Executor -> Expression for query semantics.
- Session/Variables -> Executor for user-visible runtime behavior.
- DDL -> Infoschema/Meta -> Domain for schema lifecycle.
- Store/KV/DistSQL -> Executor for distributed execution behavior.
